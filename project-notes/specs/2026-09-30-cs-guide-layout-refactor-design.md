# AI 不完全指北：CS 自学指南式布局重构设计

## 目标

在保留当前蓝色视觉体系、Markdown 内容和 Material for MkDocs 功能的前提下，将站点重构为类似“CS 自学指南”的文档阅读布局：顶部为紧凑工具栏，左侧为完整学习导航，中间为正文，右侧为当前文章目录。

本次重构只改变信息呈现和导航体验，不改写正文内容，也不更换站点框架。

## 设计原则

- 保留现有深蓝、浅蓝和亮蓝配色，以及明暗模式。
- 以文档阅读效率为优先，不做营销落地页式的大幅装饰。
- 桌面端让学习路径始终可见，移动端则把导航收进抽屉。
- 优先使用 Material for MkDocs 的原生结构和配置，减少主题升级时的维护成本。
- 不引入账号、阅读进度、评论或其他与本次布局无关的功能。

## 页面骨架

### 顶部工具栏

顶部栏保留站点 Logo、站名、搜索入口和明暗模式切换。移除第二行顶部分类标签，让导航只保留一个明确入口。

桌面端顶部栏保持紧凑并固定在视口顶部。移动端增加菜单按钮，用于打开左侧导航抽屉。

### 左侧学习导航

桌面端左侧栏常驻，完整展示以下层级：

1. 首页
2. 引言
3. 第一部分：计算机第一课
4. 第二部分：大模型与 Agent
5. 第三部分：学习资源总库
6. 关于

三大部分可展开和折叠；访问子页面时，其父级保持展开，当前页面使用现有亮蓝色高亮。导航栏拥有独立滚动区域，长目录不会推动正文布局。

### 正文区

正文位于左侧导航和右侧文章目录之间。阅读宽度保持舒适，但整体位置比当前页面更靠近左侧导航，减少无效留白。

标题、正文、代码块、表格、提示框和 Mermaid 图表继续沿用现有内容样式。普通文章不增加额外封面或横幅。

### 右侧文章目录

桌面宽屏下继续显示当前页面的二级、三级标题目录，并跟随阅读位置高亮。屏幕宽度不足时，按 Material for MkDocs 的响应式规则隐藏，不与正文争夺空间。

## 首页处理

首页继续保留当前介绍、操作按钮、安全提示和“三大部分”入口，不改写内容结构。

三张入口卡片将降低视觉重量：缩短高度、减弱阴影和悬浮幅度，使其更接近文档导航入口。首页同样使用左侧完整导航和右侧页内目录，以保持全站一致。

## 实现策略

采用“MkDocs 配置调整 + 现有样式表定制”的实现方式，不覆盖完整主题模板。

- `mkdocs.yml`：移除顶部标签式导航特性，调整导航层级的展示行为，保留搜索、跟踪、返回顶部、代码复制等功能。
- `docs/assets/stylesheets/extra.css`：调整顶部栏、三栏网格、侧栏滚动、正文宽度、导航层级、首页卡片和响应式样式。
- `tests/verify_site.py`：更新桌面布局断言，并保留暗色模式、移动端抽屉、无横向溢出和 Mermaid 渲染验证。
- 正文 Markdown 文件：原则上不修改；只有在验证发现首页专用标记不足时，才做最小的类名调整。

不新增 JavaScript。导航展开、当前项跟踪、搜索和移动端抽屉均使用主题现有能力。

## 响应式规则

- 宽屏桌面：左侧学习导航、正文、右侧文章目录同时显示。
- 中等宽度：优先隐藏右侧文章目录，保留左侧导航和正文。
- 手机：左右侧栏均不常驻；左侧导航通过顶部菜单按钮打开，正文占满可用宽度。
- 所有断点下不得产生页面级横向滚动。

## 可访问性与动效

- 保留键盘焦点轮廓和足够的文字对比度。
- 导航展开控件和移动端菜单继续使用主题提供的可访问标签。
- 交互动画只使用短时颜色、边框和位移过渡。
- 用户启用“减少动态效果”时，继续关闭非必要动画。

## 验证方式

1. `mkdocs build --strict` 必须成功。
2. 桌面端验证顶部只有一层工具栏，左侧显示完整主导航，正文和右侧文章目录位置正确。
3. 验证当前页面高亮，父级分组在子页面中保持展开。
4. 验证浅色与深色模式的文字、导航和卡片均可读。
5. 验证 390px 手机视口下导航抽屉可打开和关闭，正文无横向溢出。
6. 验证搜索、Mermaid 图表和现有主要页面链接正常工作。
7. 保存桌面、深色和移动端截图，用于视觉复核。

## 完成标准

- 页面在桌面端呈现清晰的“左侧学习导航 + 中间正文 + 右侧文章目录”布局。
- 顶部不再出现第二行分类标签。
- 全站继续使用当前配色和暗色主题。
- 首页和普通文章页使用统一的文档骨架。
- 现有内容、搜索、代码复制、Mermaid 和移动端导航功能无回归。
- 严格构建和自动化页面验证通过。
